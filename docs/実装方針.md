# 実装方針

## 基本方針

> **結論：MVPは，GitHub Pagesで公開できる静的サイトとして，ブラウザ内の計算と事前生成データで完結させる．**

現時点では，HTML，CSSおよび依存ライブラリを持たないJavaScript ES Modulesを使用する．要件上の必要性が生じるまで，フレームワーク，ビルド処理，サーバー，データベースおよびクラウド関数を追加しない．

## JavaScriptの分担

> **結論：画面制御，公開データ読込および採算計算を分離する．**

| ファイル | 役割 |
|---|---|
| `assets/js/app.js` | 初期化，フォーム制御および各処理の接続 |
| `assets/js/data-loader.js` | 公開データの取得と版の整合性確認 |
| `assets/js/calculator.js` | backend仕様と一致するブラウザ採算計算 |
| `assets/js/prefectures.js` | 都道府県選択肢 |

## backend連携

> **結論：frontendは，backendが生成した3種類のJSONを`data/`から読み込む．**

| ファイル | 用途 |
|---|---|
| `data/public-data.json` | ブラウザ計算に必要な公開データ |
| `data/metadata.json` | スキーマ版，データ版，生成日時および出典概要 |
| `data/calculation-cases.json` | frontend計算とbackend基準計算の一致確認 |

公開データとメタデータの`schema_version`および`data_version`が一致しない場合は，計算機能を有効にしない．秘密情報またはbackendの内部データへ直接接続しない．

## 未実装時の扱い

> **結論：計算式または検証済みデータが未確定の場合，計算ボタンを無効にし，架空の結果を表示しない．**

`data_version`が`uninitialized`である場合，または`calculator.js`の基準計算が未実装である場合は，利用できない理由を画面に表示する．

## テスト

> **結論：計算機能を有効にする前に，入力検証，データ版の整合性およびbackend基準計算との一致を確認する．**

通常ケース，上振れ・標準・下振れ，補助金を含めないケース，境界値および不正入力を確認する．計算式と丸め規則はbackendの計算仕様を正とする．
