# 公開データ

## 役割

> **結論：backendが生成・検収した公開成果物を，原バイトのまま受け取る．**

inputにはv0.2.0で採用した6JSONを保持する．schema_versionは12.0.0-review.1，data_versionは20261010-tokyo-equipment-base-trial.3である．受領時は全ファイルの同版・ID・SHAと[frontend連携仕様](../../backend/dist/docs/frontend連携仕様.md)を照合する．公開データをfrontendで手修正せず，変更はbackendの正本から生成する．

## 接続

> **結論：国・都道府県の正規化データと，市区町村の既存データを併用する．**

srcのadapterで公開成果物を計算・表示へ渡す．掲載と診断の対象集合は同一とは限らない．金額不明・対象外・未対応の枝も掲載と根拠へ保持し，算入できる制度だけを診断へ渡す．受付開始前でも，公式募集・金額・適用条件が確認でき，将来の所定期間を満たす前提の制度は算入する．状態表示は受付開始前のままとする．

## QA用データ

> **結論：固定ケースと受領検査はqaに置き，公開サイトから実行時に読み込まない．**

公開計算の基準入力はqa/fixtures，機械検査はqa/testsを使う．受領版・ハッシュと本番配信はリリースごとに照合し，公開履歴は[リリースノート](../CHANGELOG.md)の公開commit・tag・Actions実行先を参照する．新しい版は同じ範囲のPASSを無条件で継承しない．
