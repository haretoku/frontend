# data

## 役割

> **結論：dataは，backendの公開成果物を受け取り，版を検証してsiteへ提供する．**

`input/`にはbackendの`dist/output/`から受け取った`public-data.json`と`metadata.json`を置く．受領ファイルをfrontend独自の判断で手修正しない．`src/data-loader.js`は両ファイルを読み込み，`schema_version`と`data_version`の一致を確認する．秘密情報及びbackendの内部処理用データを含めない．公開契約に含まれる未確認状態・欠損値・参考情報はそのまま保持し，確定値や制度不存在へ変換しない．

## QA用データ

> **結論：実行時に不要なbackend基準計算ケースはdataではなく`qa/fixtures/`へ置く．**

`calculation-cases.json`は画面表示には使用せず，frontend計算とbackend基準計算の一致確認だけに使用する．

## 制度年度単位の受入

> **結論：新契約は親制度の規則から受け取り，既存の診断処理へ渡す内部配列を構成する．**

`src/scheme-adapter.js`は`subsidy_schemes`と明示対応表を検証し，旧規則ID・評価順序・未配置規則を保持する．新形式では互換flat配列を入力正本にしない．loader経由の画面・記事と計算関数の直接呼出しに適用し，11.xの既存経路も維持する．一覧は親IDで制度を識別し，明示retained枝だけが契約の`catalog_branch_id`で互換catalogを参照する．名称・URLから親を推定しない．
