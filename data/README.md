# 公開データ


## 国県版の受領

> **結論：地域入力は都道府県だけとし，補助金は国・都道府県を受領する．**

schema 13の同版6JSONと共通評価器をbackendの固定書出し処理から受領する．公開JSONの手修正は行わない．市区町村制度は掲載・算入しない．県制度の地域限定条件を全県へ広げず，入力で判断できない条件は非算入候補とする．旧URLの市区町村指定は無視する．

## 役割

> **結論：backendが生成・検収した公開成果物を，原バイトのまま受け取る．**

inputには次回公開候補の6JSONを保持する．schema_versionは13.0.0，data_versionは20261013-national-prefectures.1である．受領時は全ファイルの同版・ID・SHAと[frontend連携仕様](../../backend/dist/docs/frontend連携仕様.md)を照合する．公開データをfrontendで手修正せず，変更はbackendの正本から生成する．

## 接続

> **結論：国・都道府県の正規化データだけを接続する．**

srcのadapterで公開成果物を計算・表示へ渡す．掲載と診断の対象集合は同一とは限らない．金額不明・対象外・未対応の枝も掲載と根拠へ保持し，算入できる制度だけを診断へ渡す．受付開始前でも，公式募集・金額・適用条件が確認でき，将来の所定期間を満たす前提の制度は算入する．状態表示は受付開始前のままとする．

## QA用データ

> **結論：固定ケースと受領検査はqaに置き，公開サイトから実行時に読み込まない．**

公開計算の基準入力はqa/fixtures，機械検査はqa/testsを使う．受領版・ハッシュと本番配信はリリースごとに照合し，公開履歴は[リリースノート](../CHANGELOG.md)の公開commit・tag・Actions実行先を参照する．新しい版は同じ範囲のPASSを無条件で継承しない．

## 公開データの共通取得

> **結論：一覧と診断の接続は共通loaderでHTTP・版を検証し，受領JSONは原バイトのまま保持する．**

`src/data-loader.js`の`loadJson`はHTTP失敗を伝え，`loadFrontendData`は公開データとmetadataのschema_version・data_versionを照合して制度年度契約を受け取る．一覧と診断はこの入口を使い，表示表のID・SHA・計算規則との結合検査も保持する．frontendで受領値を補完・手修正しない．
