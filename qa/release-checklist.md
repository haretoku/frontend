# リリースチェックリスト

## 使い方と完了の判断

> **結論：各リリースで全項目の適用と結果を記録し，公開成功と公開後の残件解消を分けて報告する．**

**MUST**：公開前・公開直後・公開後の確認にこの一覧を使う．対象版・公開コミット・変更範囲・担当・確認日を固定し，項目IDごとの結果と根拠を[QA記録](README.md)の当該版へ残す．運営上の残件は[開発計画](../../business-research/運営/開発計画.md)，外部サービスの現況は[運営方針](../../business-research/運営/運営方針.md#公開運用)へ反映する．リリースごとの新しい台帳は作らない．

|結果|記録する内容|
|---|---|
|PASS|完了した範囲・実施者・根拠．既存PASSの再利用は対象・再利用元・不変性も明記|
|FAIL|不合格の内容・影響・対応先|
|未確認|未実施・接続不能などの理由と次の対応|
|対象外|適用しない理由．未実施を対象外へ置き換えない|
|外部反映待ち|送信受理等の実施済み部分，反映未確認の部分，再確認の担当・時期|
|ユーザー指示で延期|延期した項目・指示・残る影響．PASSにはしない|

公開前の適用MUSTにFAIL・未確認が残る場合は公開しない．ユーザーが延期を明示した項目は指示の範囲を記録して判断する．公開承認は[完了条件](../../business-research/運営/運営方針.md#検収代理承認完了条件)に従い，対象版の公開指示を既に得ている場合は同じ承認を求め直さない．

公開後の項目が残れば「公開済み／後処理残」と報告し，残件のID・理由・対応先を示す．MUSTの延期，RECOMMENDの採否，NITSの残し方も記録する．実際の検索掲載・共有表示が未確認なのに，配信成功だけで「すべて完了」としない．

## 公開前

> **結論：公開する版，動作，公開範囲，外部導線を確認してから，承認された版を公開する．**

|ID|優先度|チェック項目と完了条件|
|---|---|---|
|P01|MUST|版番号・変更範囲・対象コミット・既公開の切戻し先を特定する．未承認の変更や作業中の成果物を混ぜない|
|P02|MUST|変更した本文・図・ハレナのまとめ・質問回答・計算定義・診断の説明をそろえる．新しい数値・出典・仮定と公式データを区別し，数値変更時は所定のデータ・計算検収もそろえる|
|P03|MUST|関連検査と公開用 `pnpm run test:public`・`pnpm run build:pages` が合格し，対象版を特定できる．コード不変の文書更新だけで全件検査を再実行しない|
|P04|MUST|変更ページをPC・スマホの実画面で確認する．本文・図表・全質問・ボタン・開閉・はみ出しをページごとに確認し，MAP→記事→診断→プラン→相談の操作と保存・再読込を影響範囲で検査する．公開済みの対応画面または同種の部品と同じ表示幅・高さで見比べ，文字・余白・色・カード・アイコン・対話・ボタンの統一感を確認し，意図した変更と退行を分けて記録する．幅変更と実端末確認を区別する|
|P05|MUST|公開対象の必要な独立検収を実装担当とは別の担当で終える．MUSTを解消し，RECOMMEND／NITSの採否を記録する．不変範囲は版・条件・範囲を特定した既存検収を再利用できる|
|P06|MUST|内部リンク・アンカー・PDF・旧URL・404・canonical・サイトマップ・robots／noindexと，出典・公式リンクへの到達を確認する．成果物へQA原稿・内部MD・認証情報・開発経路を混入させない|
|P07|MUST|TOPと変更ページのtitle・description・OG／Twitter用メタ・サイト名・faviconを確認し，JS表示後も旧titleへ戻らない．共有画像の新旧URL・互換先の実画像，形式・寸法・小サイズの可読性を確認し，旧写真を意図せず配信し続けない．記事専用OG画像は維持する|
|P08|MUST|広告の提携・ロゴ／素材の使用条件・広告URLと計測画像の組・広告表記を確認する．条件未確認の素材は合意済みの代替表示を使う．比較表のロゴと相談カードのリンクをそろえ，通常リンクと推薦を区別する．申込みをせず受付ページへの到達を確認し，広告掲載ページの現行URL一覧を用意する|
|P09|MUST|変更した主要導線のGAイベント・固定識別子・送信条件を確認する．広告クリックと通常リンクを区別し，診断入力・金額・個人情報等を送らない．送信項目と実受信の確認範囲を記録する|
|P10|MUST|変更内容・検査結果・残件・切戻し先を提示し，対象版の公開承認を確認する．候補の保存・同期・検収合格を公開承認へ読み替えない|

ページ別・入力別の詳細は[必須ケースと検査範囲](README.md#必須ケースと検査範囲)，広告と計測は[画面設計](../site/docs/画面設計.md)を正本とする．初回・全面再構成では新規ページを全件確認し，パッチでは変更箇所と影響範囲に絞る．

## 公開直後

> **結論：公開処理の成功だけで終えず，本番の配信内容と主要操作を確認し，公開版を固定する．**

|ID|優先度|チェック項目と完了条件|
|---|---|---|
|D01|MUST|Pagesのbuild・deployが成功し，実行URLと実際の公開コミットが承認対象と一致する|
|D02|MUST|本番のHTTPS・正規化・主要URL・変更資産・404を確認し，変更HTML／JS／CSS／画像／公開データを成果物と照合する．機能や設定が不変の既存確認は，その範囲を記して再利用する|
|D03|MUST|本番の変更画面と主要導線を確認する．新title・OG画像・ロゴ，MAP／記事／診断／相談・外部リンク・保存のうち変更に影響する操作を確認する．GA導線を変更した場合は実受信まで確認するか，未確認の残件として記録する|
|D04|MUST|実際の公開コミットへ注釈付きタグを付け，GitHub Release・CHANGELOG・QA・開発計画・運営方針の公開版と結果をそろえる．タグは付け替えない|

重大な本番不具合があれば影響と対応を報告し，承認範囲に従って修正又は切戻しを行う．一時確認タブ・補助プロセスを整理し，共有開発サーバー等を保持する場合は用途を残す．

## ASP・Google・リンク共有

> **結論：広告リンクの動作，ASPへの報告，Googleへの送信，実際の検索・共有表示を別項目として確認する．**

|ID|優先度|チェック項目と完了条件|
|---|---|---|
|E01|MUST|広告の新設・掲載ページやURLの変更時は，実際に広告リンクを表示するページを確認して各ASP案件へ報告する．全ルート一覧や共通JS内の広告URLだけで掲載先と判断しない．既存登録と照合し，不足・過剰・廃止URLを整理する．提出・削除後の件数と対象URL一致を記録し，旧URL報告やリンク到達だけでPASSにしない|
|E02|MUST|ページ追加・削除・正規URL／タイトル／共有設定等の変更に応じ，Search Consoleでサイトマップ送信・対象URLの更新依頼を行う．送信・受理・最終読込み・検出数・実際のインデックス登録を分けて記録する．同一URLの短時間の再送信は繰り返さない|
|E03|RECOMMEND|変更した検索タイトル・説明・アイコンや新規記事の登録を実際の検索表示で確認する．旧表示なら配信確認とは別に外部反映待ちとし，担当と次回の確認時期を開発計画へ残す|
|E04|RECOMMEND|共有設定・画像の変更時は，LINE等の実際の新規共有でタイトル・説明・画像を確認する．端末の添付画像は確認時刻とともに根拠にできる．旧画像ならメタ情報が正常でも外部反映待ちとする．許可なく他人へテスト送信しない|
|E05|RECOMMEND|CI依存・ランタイム等の非阻害警告や運用残件を確認し，対応要否と次の作業を記録する．今回の公開不具合と区別する|
|E06|NITS|リリースノートの用語・日付・リンク・軽微な表記をそろえる|

ASP操作や外部表示の確認ができない場合は理由を残し，ユーザーの延期指示を保持する．未確認の解消を理由に，無許可の実申込み・契約・連絡・設定変更を行わない．

## 結果の記録

> **結論：既存の版別QAへ項目ID・結果・根拠・残件を記録し，次の確認へ引き継ぐ．**

版別QAの冒頭に対象版・コミット・範囲・担当・確認日を置き，次の列で全IDを記録する．同じ根拠の項目は範囲を明記してまとめてもよいが，未確認・外部待ち・延期は独立行にする．

|ID|結果|確認範囲・根拠・実施者|残件・担当・次の確認時期|
|---|---|---|---|
|対象ID|上記の結果区分|実行URL，既存QAの節，確認画像又は入力条件等|なし，又は具体的な次作業|

最終報告は「公開前確認済み／公開済み／公開済み・後処理残」を明示し，残るMUSTと外部反映待ちを示す．検索反映やASP報告が残る状態を，サイトの配信成功だけで全項目完了へ読み替えない．
